# 思考AI設計

この文書は、フェイズ6で実装する思考AIの設計上の正本とする。
実装とこの文書が矛盾する場合は、先にこの文書を更新してから実装を変更する。

## 難易度とシナリオCOMの拡張カード

- Easy：自分の手札2枚を思考対象から外し、連続召喚の先読みを行わない。COMに拡張カードを追加しない。
- Normal：自分の手札1枚を思考対象から外し、シナリオでは下表の拡張カードを追加する。
- Hard：手札をすべて思考対象とし、シナリオでは下表の拡張カードを追加する。
- 無視する手札はターンごとに選び、そのターン中は固定する。人間側の手札や表示には影響しない。
- メインフェイズで実際の手札が5枚あり、思考対象の手札に合法な召喚・魔法使用がない場合、通常評価より優先して最大コストの手札を1枚捨てる。除外された手札は捨てず、同コストなら手札順を優先する。1ターン1回の破棄制限に従う。
- 拡張カードは各戦のCOMのデッキについて `deck-expansion-win-rate-gains.json` の値が高い順に選ぶ。同率は拡張カード定義の登録順。
- 各戦の基本デッキに追加し、前戦のCOMの拡張カードは持ち越さない。プレイヤーの報酬選択・持ち越しは従来どおり。

| シナリオ | COMへの追加 |
|---|---|
| 1戦目 | なし |
| 2戦目 | 3位を2枚 |
| 3戦目 | 3位を2枚、2位を2枚 |
| 4戦目 | 1位・2位・3位を各2枚 |
| 5戦目 | 1位・2位を各4枚（3位はなし） |

フリーバトルは連戦数を持たないため拡張なし。難易度による手札の制限と連続召喚の先読みの有無を適用する。

## 目的

- ルール上可能な行動から、評価値が最も高い行動を選択する。
- 深いゲーム木探索に頼らず、短い時間で行動を決定する。
- 評価の内訳を確認できるようにし、局面テストを使って継続的に調整できるようにする。
- UIとAIで合法手判定や戦闘処理を重複実装しない。

## 初期実装で行わないこと

- アルファベータ法による深い探索
- モンテカルロ木探索、情報集合モンテカルロ木探索
- 相手の非公開手札の推定
- 山札順の参照または予測
- 複数ターンにまたがる行動列の探索
- 魔法を展開可能手札価値のナップサック候補へ含めた同時使用列の評価

これらは初期AIとの対戦結果を確認した後、必要なものだけ追加する。

## 情報の扱い

《大喰い》は攻撃プレビューにも本番と共通の山札破棄を適用する。攻撃力は発動前に確定し、破棄後の捨て札を既存の評価で扱う。専用の評価係数は追加しない。

《召喚酔い》は召喚ターンだけ、印刷攻撃力×0.75を盤面価値へ加える。自分と相手で符号を反転して同じ計算を使い、破壊された場合は戦闘プレビュー内でも加点が消える。次ターン以降は加点せず既存の攻撃評価に任せる。追加探索は行わない。

AIは以下の情報だけを評価に使用する。

- 公開されている盤面、配置魔法、捨て札
- 両プレイヤーのHP、マナ、手札枚数、山札枚数
- AI自身の手札
- 現在の手番、フェイズ、攻撃済みかどうか

AIは内部の`GameState`に格納されていても、次の情報を評価に使用しない。

- 相手の手札内容
- 両プレイヤーの山札順

相手の召喚能力は、公開盤面、マナ、手札枚数からのみ評価する。
《捕獲》の評価では実際の相手手札やデッキ構成を参照せず、進軍1の仮想クリーチャーを基準にする。

## 全体構造

メインフェイズとバトルフェイズの意思決定を分離する。
メインフェイズでは攻撃を選択せず、バトルフェイズへ移った後に改めて盤面を評価して攻撃を決定する。

評価と行動計画は次の3要素で構成する。

1. 基礎評価
2. 実状態を更新するメインフェイズロールアウト（Normal・Hard）
3. 攻撃プレビュー評価

```text
メインフェイズで何もしない場合
  現在盤面からバトルへ進んだ場合の評価

メインフェイズで行動する場合
  行動を実際に適用する
  → Easy：その直後のバトル開始評価
  → Normal・Hard：残った手札から、実状態を更新しながら召喚を継続する
    → 各途中状態のうち最良のバトル開始評価

バトルフェイズ
  各攻撃候補と「攻撃しない」を比較
  → 最善の1つを実行
```

メインフェイズでは各合法手を1回適用する。Easyはその直後の`evaluateBattleEntry`を比較し、Normal・Hardはそこから一貫した召喚ロールアウトを行った評価を比較する。
最良の行動を1つ実行した後、実際の状態から同じ処理を繰り返す。
「何もしない」評価以上になる行動がなければ、バトルフェイズへ進む。

バトルフェイズへ進んだ後は、それまでのメインフェイズ評価を使い回さず、攻撃候補を改めて評価する。

## 合法手の列挙

合法手は`GameManager`が一元的に列挙する。
AIが盤面や手札を直接調べて、独自に合法性を判定してはならない。

メインフェイズで列挙する実行候補は次のとおり。

- 各手札クリーチャーを各召喚可能位置へ召喚する。
- 手札の布陣を配置する。
- 使用可能な起動型能力を使う。

「何もせずバトルフェイズへ進む」は、実行候補とは別の比較基準として常に用意する。

バトルフェイズで列挙する選択行動は次のとおり。

- 攻撃可能な各グループで攻撃する。
- 攻撃せずターンを終了する。

メインフェイズ中に攻撃操作を受け付けるUIはショートカットとして扱う。
内部ではメインフェイズを終了してバトルフェイズへ移った後、指定された攻撃を実行する。

次の処理は選択肢ではなく、シミュレーション中に即時解決する強制処理とする。

- キープアップ処理
- 戦闘結果の確定
- ダメージ表示終了後に行われるゲーム上の処理
- 行動しないフェイズの通過

列挙された全アクションは、同じ状態へ`GameManager.applyAction`して例外を発生させないことをテストする。

## 評価値の向き

評価値は常にAIプレイヤーの視点で計算する。

- 正の値: AIが有利
- 負の値: AIが不利
- 大きい値: より望ましい

原則として、各要素をマナ相当の単位へ寄せる。

```text
評価値 = 自分の点数 - 相手の点数 + 局面固有の補正
```

相手の非公開手札内容は点数へ含めないため、完全な対称評価にはならない。

評価値の比較では`1e-9`以内の差を同点として扱い、終局級の加点と減点を相殺した際の浮動小数点誤差で行動を変えない。同点時は、メインフェイズとバトルフェイズでは行動しない選択を優先し、行動同士では合法手の列挙順を維持する。相手の応手同士が同点の場合は、AI側の評価がより低くなる応手を優先する。

## 評価の内訳

評価関数は合計値だけでなく、調整可能な内訳を返す。

```ts
type EvaluationBreakdown = {
  terminal: number
  hp: number
  mana: number
  boardMaterial: number
  handReserve: number
  deployableHand: number
  upkeepMana: number
  upkeepDamage: number
  marchControl: number
  myAttackPotential: number
  opponentAttackThreat: number
  total: number
}
```

内訳をログまたはデバッグ表示から確認できるようにする。
合計値だけを返す実装にはしない。

## 初期パラメータ

初期値は実装開始時の基準であり、局面テストとAI同士の対戦結果を元に更新する。

| パラメータ | 初期値 | 意味 |
| --- | ---: | --- |
| 勝利 | 20000 | 相手HPを0以下にした状態 |
| 敗北 | -10000 | 自分HPが0以下になった状態 |
| HP | 4 | HP1点あたりの価値 |
| マナ | 1 | 所持マナ1点あたりの価値 |
| 場のカードコスト | 1 | 場のクリーチャーの召喚コスト1点あたりの価値 |
| クリーチャーの手札予備価値 | 0.3 | 自分のクリーチャーの召喚コストへ掛ける値 |
| 魔法の手札予備価値 | 2.0 | 自分の手札にある魔法1枚の固定価値 |
| 《生命の雫》温存係数 | 0.5 | 除外可能な青クリーチャーから得る回復価値のうち、手札に残す選択肢として評価する割合 |
| 次回マナの係数 | 1.2 | 次のキープアップで得る追加マナへ掛ける値 |

値を変更した場合は、変更理由と影響を受ける局面テストも更新する。

## 終端評価

勝利点の絶対値は敗北点の絶対値より大きくする。
現在のターンで勝利できる行動は、その後のターンで不利になる可能性より常に優先する。

相手HPが0以下になった状態は、その時点で勝利として評価を終了する。
ターン終了、次プレイヤーのキープアップ、相手の攻撃評価へ進めず、他の評価項目も加算しない。
自分HPが0以下になった状態も同様に敗北として評価を終了する。
山札切れは終端状態ではなく、引き分けも評価しない。

```ts
const evaluate = (
  manager: GameManager,
  aiPlayerId: PlayerId,
): EvaluationBreakdown => {
  const winner = getWinner(manager.state)

  if (winner === aiPlayerId) return createTerminalBreakdown(20000)
  if (winner !== null) return createTerminalBreakdown(-10000)

  return evaluateNonTerminalState(manager, aiPlayerId)
}
```

`createTerminalBreakdown`は`terminal`と`total`へ同じ勝敗点を設定し、それ以外の内訳を0にする。
終端状態で処理を打ち切ることを正とし、勝利点と敗北点の差だけに依存して後続ターンの評価を相殺する実装にはしない。

## 基礎評価

基礎評価は仮想的な後続行動を呼び出さず、現在の状態だけから計算する。

```text
基礎評価
= HP差 × HP係数
+ マナ差 × マナ係数
+ 場のクリーチャーの召喚コスト差
+ 自分の手札の予備価値
+ 次回キープアップの追加マナ差
+ 進軍可能範囲の差
```

場のクリーチャーは召喚コストを基本価値とする。
攻撃力、防御力、位置補正、反撃は、主に攻撃プレビュー評価を通じて点数へ反映する。

配置魔法のカード自体へ場の素材点を加点しない。
配置魔法によるシールド、マナ、攻撃制限への実際の影響を各評価項目で加点する。

手札カードは、場のカードより低い予備価値を持つ。
AI自身の手札にあるクリーチャーを`召喚コスト × 0.3`、魔法を1枚`2.0`として評価する。
魔法は0コストでも使い切りであるため、即時効果が小さい局面で温存しやすいよう、クリーチャーとは別の固定値を使う。
《生命の雫》が手札に1枚以上ある場合は、さらに`捨て札の青クリーチャー数 × HP係数 × 0.5`を温存価値として1回だけ加える。
同名カードが複数あっても共有する除外候補を重複評価せず、《生命の雫》をすべて思考対象から除外した場合はこの加点も行わない。
手札枚数そのものには固定価値を付けない。
相手の手札内容は参照せず、公開されている手札枚数から平均コストや予備価値を見積もることもしない。
手札から現在使えることで生じる具体的な価値は、クリーチャーでは展開可能手札価値、魔法では使用後状態の評価へ反映する。

手札の予備価値は、今後のターンに使用できるカードを手札へ残す価値を表現する。
場のカードと同じ価値にはせず、召喚前のカードを過大評価しない。

## 攻撃プレビュー評価

攻撃評価は、攻撃による各効果を別々に最大化して合計してはならない。
1ターンに攻撃できるのは1グループだけなので、攻撃可能な各グループについて一つの戦闘結果を作り、その中で最もよい結果だけを採用する。

自分の各攻撃候補では、倒せる敵クリーチャーの価値、相手プレイヤーへ与えるダメージ、反撃で失う自クリーチャーの価値を一つの結果として評価する。
相手の各攻撃候補では、倒される自クリーチャーの価値、自分が受けるプレイヤーダメージ、相手が反撃で失うクリーチャーの価値を一つの結果として評価する。
相手の応手は、「自分の評価を最も下げる攻撃」ではなく、「相手自身の評価を最も上げる攻撃」とする。
「攻撃しない」も相手の応手に含める。相手評価が同点の場合は、自分の評価がより低くなる応手を選ぶ。

```ts
type CombatPreview = {
  attackerId: PlayerId
  attackingGroup: { startIndex: number; endIndex: number }
  destroyedCardIds: CardInstanceId[]
  refundedMana: Partial<Record<PlayerId, number>>
  playerDamage: number
  nextState: GameState
}
```

戦闘プレビューは、通常の戦闘解決と同じ処理を使用する。
評価関数内に攻撃、反撃、破壊、マナ返還のルールを再実装してはならない。

```text
自分の攻撃ポテンシャル
= max(攻撃後の基礎評価 - 現在の基礎評価, 0)

相手の最善応手
= argmax(応手後の相手視点の基礎評価)

相手の攻撃脅威
= max(現在の基礎評価 - 相手の最善応手後の自分視点の基礎評価, 0)
```

相手の応手を選ぶ評価では基礎評価だけを使い、さらに相手の応手を呼び出さない。
この相手視点の基礎評価では、相手の非公開手札の内容を参照せず、手札の予備価値を0とする。
これにより、《採掘》を倒す攻撃より別の攻撃の方が相手にとって高価値なら、《採掘》が生存する結果を予測する。
この機会損失を表すための固定の「ジレンマボーナス」は追加しない。

自分の手番中に実行できる攻撃ポテンシャルは、そのまま全額を評価する。
手番を渡した後は相手が先に行動して盤面を変えられるため、相手手番中に仮定する自分の攻撃ポテンシャルだけを0.75倍する。
相手の攻撃脅威にはこの係数を掛けない。

戦闘プレビューでは演出用の0.5秒待機を行わず、戦闘結果を即時確定する。

### 撃破価値とマナ返還

場のクリーチャーを召喚コスト、所持マナをマナ点として評価すると、通常の破壊による返還が自然に反映される。

```text
コスト4の通常クリーチャーを破壊
場から -4、返還マナ +2、実質損失 -2

コスト4の《消滅》を破壊
場から -4、返還マナ +0、実質損失 -4
```

《消滅》へ固定の減点を追加せず、戦闘結果の返還マナ0として扱う。

### プレイヤーダメージ

プレイヤーダメージは、戦闘後のHP差を通じて評価する。
与えるダメージが相手の残りHP以上なら勝利点を使用する。
受けるダメージが自分の残りHP以上なら敗北点を使用する。

## 展開可能手札価値

展開可能手札価値は、評価内訳と局面テストのために残す補助指標である。
独立候補の加算は実際の配置順を表さないため、メインフェイズの行動選択には直接使用しない。

《撤収》《橋頭堡》のように、後続の召喚によって価値が発生する状態を、深い行動列の探索ではなく「現在の手札から展開できる戦力」として評価する。

手札の各カードについて、現在の状態で使用できるすべての配置先を調べる。
同じカード、同じ有効コストの候補が複数ある場合は、基礎評価と攻撃プレビュー評価が最も高くなる配置だけを残す。

```ts
type HandPlayCandidate = {
  cardId: CardInstanceId
  action: GameAction
  effectiveCost: number
  value: number
  baseValue: number
  terminalSwing: boolean
}

const getHandPlayCandidates = (
  manager: GameManager,
  cardId: CardInstanceId,
): HandPlayCandidate[] =>
  keepBestCandidateForEachEffectiveCost(
    getLegalPlayActions(manager, cardId).map((action) => {
      const nextManager = applyActionImmediately(manager, action)

      const current = evaluateBattleEntry(manager)
      const next = evaluateBattleEntry(nextManager)

      return {
        cardId,
        action,
        effectiveCost: getEffectiveActionCost(manager, action),
        value: next.total - current.total,
        baseValue: getBaseTotal(next) - getBaseTotal(current),
        terminalSwing: newlyFindsVictory(current, next)
          || newlyAvoidsDefeat(current, next),
      }
    }),
  )
```

`evaluateBattleEntry`は基礎評価と攻撃プレビュー評価だけを含み、展開可能手札価値を呼び出してはならない。
これにより評価は再帰せず、思考時間や探索深度の制限を必要としない。

### マナ制約

現在のマナを複数のカードで重複して使ったものとして評価してはならない。
各カードを0回または1回だけ選べる多項目ナップサックとして扱い、合計有効コストが現在マナ以下になる組み合わせのうち、展開価値の合計が最大になるものを採用する。

各候補を単独で評価した結果、複数の候補が同じ致死攻撃を成立させる、または同じ敗北を回避することがある。
この勝敗級の差分をそのまま足すと、実際には一度しか起きない勝利・敗北回避を手札枚数分だけ重複加算してしまう。
DPは「勝敗級差分をまだ加えていない状態」と「すでに加えた状態」の2つを持ち、組み合わせ全体で勝敗級差分を1回だけ加える。
2枚目以降の勝敗級候補は、攻撃プレビューを除いた基礎評価の差分`baseValue`だけを加える。

```ts
const deployableHandValue = (
  manager: GameManager,
  playerId: PlayerId,
): number => {
  const mana = manager.state.players[playerId].mana
  const candidatesByCard = getCandidatesByCard(manager, playerId)
  const bestWithoutTerminalByMana = Array<number>(mana + 1).fill(0)
  const bestWithTerminalByMana = Array<number>(mana + 1).fill(-Infinity)

  for (const candidates of candidatesByCard) {
    const previousWithoutTerminal = [...bestWithoutTerminalByMana]
    const previousWithTerminal = [...bestWithTerminalByMana]

    for (let availableMana = 0; availableMana <= mana; availableMana += 1) {
      for (const candidate of candidates) {
        if (candidate.effectiveCost <= availableMana) {
          updateTwoStateKnapsack(
            candidate,
            availableMana,
            previousWithoutTerminal,
            previousWithTerminal,
            bestWithoutTerminalByMana,
            bestWithTerminalByMana,
          )
        }
      }
    }
  }

  return Math.max(...bestWithoutTerminalByMana, ...bestWithTerminalByMana)
}
```

手札は最大5枚であり、各カードについて同じ有効コストの配置候補を1つへまとめるため、深い行動列探索にはならない。
《橋頭堡》などで同じカードに複数の有効コストが存在する場合も、コストごとの最良配置を比較できる。
実際に1枚出した後は盤面、手札、マナ、配置可能位置を更新し、展開可能手札価値を最初から再計算する。

初期実装の展開可能手札価値はクリーチャーカードだけを対象にする。
魔法は多項目ナップサックの対象に含めず、メインフェイズの直接の行動候補として評価する。
魔法を実際に使用した後は、変化した盤面、手札、マナから展開可能手札価値を再計算する。
これにより、《収穫祭》の追加マナで可能になる後続召喚も、深い行動列探索を追加せずに評価する。

この値はAI自身の手札だけから計算する。
相手の非公開手札について、展開可能手札価値を推測しない。

## メインフェイズの行動決定

独立に評価した複数の召喚候補を加算すると、同じ配置先、同じ攻撃機会、同じ敗北回避を同時に利用できるものとして過大評価する場合がある。
特に、捨て札の後だけ複数の仮想召喚価値が加算され、実際の召喚より捨て札を優先する不整合が生じる。

メインフェイズでは「何もしない」場合を現在盤面のバトル開始評価とする。
Easyは各合法なメイン行動を1回適用した直後の`evaluateBattleEntry`で判断する。攻撃プレビューと相手盤面の攻撃脅威評価は残す。実際の行動後には改めて判断するため、1ターンに複数枚を召喚することはできる。

以下の召喚ロールアウトはNormal・Hardだけで行う。各合法なメイン行動は実際に1回適用し、その後はクリーチャー召喚だけを対象に、状態を更新しながら次の処理を繰り返す。

1. 現在状態から可能な全召喚を1回ずつ実際に適用する。
2. 各召喚後のバトル開始評価を比較し、最良の召喚をロールアウト状態へ適用する。
3. 召喚可能な手札が残る限り繰り返す。
4. 開始状態を含む各途中状態のうち、最も高い評価を行動候補の点数とする。

この処理は行動回数を固定しない。手札とマナによって自然に終了し、仮想候補の点数は加算しない。

```text
何もしない評価
= evaluateBattleEntry(現在状態)

行動候補の評価
= coherentMainPlan(行動後状態)で実際に到達した
  各途中状態のevaluateBattleEntryの最大値
```

```ts
const evaluateCoherentMainPlan = (
  manager: GameManager,
  aiPlayerId: PlayerId,
): EvaluationBreakdown => {
  let current = manager
  let best = evaluateBattleEntry(current, aiPlayerId)

  while (hasLegalCreatureSummon(current)) {
    current = selectBestActualSummon(current, aiPlayerId)
    best = maxEvaluation(best, evaluateBattleEntry(current, aiPlayerId))
  }

  return best
}
```

魔法、起動型能力、捨て札は最初の合法手候補として評価する。
それらを実行した後の追加召喚はロールアウトに含めるが、ロールアウト中に魔法、起動型能力、捨て札を再帰的に選ばない。
実際に最初の行動を1つ実行した後は、更新済み状態から全合法手を改めて比較する。

```ts
while (manager.state.phase === 'main') {
  const passScore = evaluateBattleEntry(manager, aiPlayerId)
  const bestAction = getLegalMainActionCandidates(manager)
    .map((action) => ({
      action,
      score: evaluateCoherentMainPlan(
        applyActionImmediately(manager, action),
        aiPlayerId,
      ).total,
    }))
    .sort(byScoreDescending)[0]

  if (!bestAction || bestAction.score <= passScore) {
    manager = enterBattlePhase(manager)
    break
  }

  manager = applyActionImmediately(manager, bestAction.action)
}
```

同点の場合は行動せず、バトルフェイズへ進む。
行動するたびに再評価するため、マナと合法手が残っている限り、固定回数に制限されず複数回行動できる。

## バトルフェイズの行動決定

バトルフェイズへ進んだ後、攻撃可能な各グループと「攻撃しない」を改めて評価する。
メインフェイズで計算した攻撃候補をそのまま採用してはならない。

攻撃する場合と攻撃しない場合は、どちらも戦闘結果、ターン終了、次プレイヤーの強制キープアップまでを即時解決し、同じ時点の状態として比較する。
ただし、途中でいずれかのプレイヤーのHPが0以下になった場合は、その時点で終端評価を返し、それ以降のフェイズへ進めない。

```ts
const chooseBattleAction = (manager: GameManager): GameAction | null =>
  getBattleOptionsIncludingNoAttack(manager)
    .map((option) => ({
      option,
      score: evaluateAfterTurn(resolveBattleOption(manager, option)),
    }))
    .sort(byScoreDescending)[0]?.option.action ?? null
```

AIは選んだ攻撃、または攻撃しない処理を1回だけ実行する。
同点の場合は、初期実装では攻撃しない選択を優先する。

## 能力別の評価

### 撤収

- 能力へ固定点を付けない。
- 撤収後に場のカード価値が失われ、召喚コスト分のマナが増える状態を評価する。
- 増えたマナによって出せるようになった手札は、展開可能手札価値の増加として評価する。
- 撤収を実行した場合は、その後のメインフェイズ評価で合法手と展開可能手札価値を再計算する。

### 招集

- 能力へ固定点を付けず、移動後の盤面を既存の評価関数で評価する。
- 最前方の自グループの末尾に合流し、グループの攻防・位置能力・召喚候補が変わる状態を評価する。
- 自分の所属グループも移動先に含め、すでにその末尾にいる場合は合法手に含めない。
- 手札・マナ・召喚ターンは変化しない。
- 起動できるのは自分のメインフェイズだけとし、相手の攻撃直前に使えるものとして評価しない。
- 複数の《招集》持ちが末尾へ移動し続ける循環を避けるため、AIは同じ物理カードを1ターンに1回だけ招集候補として扱う。
- 招集済みの判定には`CardInstanceId`を使い、ターンが変わった時点で履歴を破棄する。
- この制限はAIの行動選択ポリシーであり、`GameManager`の合法手や人間プレイヤーの操作には適用しない。

### 橋頭堡

- 能力へ固定点を付けない。
- 実際の召喚候補が受けるコスト軽減を使用する。
- 軽減によって召喚可能になったカードと、同じマナで同時に展開できる手札の組み合わせを展開可能手札価値として評価する。
- 手札またはマナの都合で隣へ召喚できない場合、現在の即時価値は0とする。

### 採掘

- 現在有効な《採掘n》が次のキープアップで生む追加マナを評価する。
- 同じグループ内では最大値だけを使用する現行ルールをそのまま適用する。
- `追加マナ × マナ係数 × 1.2`を加点する。
- 相手が相手視点で最も得する応手を選んだ後、採掘持ちが生存するかを相手の攻撃脅威を通じて評価する。

### 砲撃

- 場にいる自分と相手の《砲撃n》をそれぞれ合計し、差に `HP係数4 × 0.75` を掛けた次回発動の予備価値を `upkeepDamage` に持つ。複数体は同じグループでも重複する。ただし下記の追加召喚リスクがある発生源は、その寄与を10%に割り引く。
- 追加召喚リスクは、次の通常マナ補充で出せるコスト2相当の「攻撃3・進軍1の敵1体」を基準に近似する。相手の手札・山札の枚数だけを参照し、両方0枚ならこのリスクを付けない。内容やデッキの構成は読まない。
- ゲーム本体と共通の進軍判定で、捕獲・自グループの配置拠点を含めて侵入可能な位置を調べる。その位置から攻撃方向にある砲撃役まで、同一グループの現在の実効防御力の合計が3以下なら危険とする。召喚による位置能力の変化、追加クリーチャーとの合流、呪文や大型の追加は近似に含めない。
- 砲撃持ちが場にいる場合だけ、既存の「攻撃しない／各グループで攻撃する」の評価へキープアップダメージの予測を追加する。
- 現在の手番の攻撃後には、次プレイヤーの砲撃をHPへ反映する。未来の手番の攻撃候補では、攻撃前にそのプレイヤーの砲撃、攻撃後に反対側の砲撃を反映する。
- AI自身の将来の砲撃を予測する場合も、相手の未探索のメイン行動があるため上記の割引を適用する。危険な発生源の期待ダメージだけで予測上の勝利を確定させない。自分の行動直後に受ける敵の砲撃と、実際に発動待ちになった砲撃は全ダメージで解決する。
- 各プレイヤーの発動は予測内で最大1回とし、HPへ反映した発動分の予備価値は取り除く。シールドは適用しない。
- 攻撃で決着した場合や先に砲撃で決着した場合、それより後の発動・攻撃は評価しない。実際の手番進行で表示待ちになった砲撃も、AIの候補採点では即時解決する。
- 自分の手番では直後の砲撃まで含む最善の攻撃候補を基準に、相手が最も得する攻撃による悪化を評価する。相手の手番では相手の最善候補と、その後の自分の攻撃可能性（0.75倍）で評価する。
- この場合、`myAttackPotential` と `opponentAttackThreat` はキープアップによる増減も含む符号付き補正となる。予測上の勝敗は実際の勝敗 `terminal` と区別し、展開可能手札価値で勝敗級の加点を重複させない。
- 破壊・買収後の盤面とコントローラーを使う。ターン終了のリボ払いで破壊されるクリーチャーも除去してから次の発動を評価する。
- 非公開の手札・ドローの内容や複数ターンの生存は仮定しない。双方の攻撃候補は従来と同様に独立して列挙し、応手の組み合わせを追加探索しない。仮想カードの生成・召喚・戦闘シミュレーションは行わず、必要な位置の到達判定を同じ見積もり内で再利用する。

### 捕獲

- 相手の手札内容は参照しない。
- デッキ内の進軍値比率や平均値は計算しない。
- 相手が進軍1の仮想クリーチャーを召喚すると仮定する。
- 現在の《捕獲》を適用した場合と、《捕獲》の進軍補正だけを無視した場合の配置可能位置数の差を評価する。

```text
捕獲評価
= 進軍1で減少した配置可能位置数 × 捕獲係数
```

- 複数の《捕獲》がある場合も固定点を合算せず、盤面全体で実際に減少した配置可能位置数を使う。
- 配置可能位置1箇所あたりの係数は0.5とする。

### 消滅

- 固定点を付けない。
- 破壊時に返還マナが発生しない戦闘結果として評価する。
- 生存中のカード価値を常に減点してはならない。

### リボ払い

- 自分の手番中の攻撃候補では、現在場にいるクリーチャーとして扱う。
- 相手へ手番を渡した後の攻撃脅威では、ターン終了時の支払いを通常ルールで解決してから盤面を評価する。
- 支払えず破壊されるクリーチャーを、相手ターンにも残る防御要員として評価してはならない。
- 評価関数側で支払い順や破壊条件を再実装せず、`GameManager`が返す支払い結果を使う。

### トリックスター

- HP差による現在の攻撃力または防御力補正を、通常の実効ステータスとして攻撃プレビューへ反映する。
- 能力へ追加の固定点を付けない。

### 略奪

- プレイヤーダメージ後に実際に得たマナを、通常のマナ評価へ反映する。
- さらに、獲得マナがある場合とない場合で、次回キープアップ後に現在の手札から支払えるクリーチャーの印刷コスト合計がどれだけ増えるかを比較する。
- 増加した印刷コストへ0.3を掛け、攻撃候補の評価へ加える。
- 配置場所、将来のドロー、相手の応手、次ターンの行動列は追加探索しない。
- 相手の《略奪》について、非公開手札を参照した次回展開価値は計算しない。

## 魔法の評価

- 手札にある魔法は、1枚あたり2.0の基礎予備価値を持つ。
- 0コストでも使い切りの魔法を小さな効果で消費しにくくし、効果量が大きい局面まで保持するため、クリーチャーの係数とは分離する。
- 《生命の雫》は、現在除外できる青クリーチャーによる回復価値の0.5倍を追加の温存価値とする。この価値は手札内で1回だけ加え、同名カードの枚数では増やさない。
- 《生命の雫》の温存価値は、使用後に得る効果を固定加点するものではなく、現在の使用選択肢を捨てずに残す価値を割り引いて表す。
- 魔法の具体的な効果へ固定点を付けず、使用後に生じた盤面、HP、マナ、攻撃可能性の変化を評価する。
- 配置魔法は実際の期限と上書き状態を含む配置後の状態から評価する。
- 《バックドラフト》は候補評価時にダメージと破壊を即時解決し、返還マナと盤面変化を反映した後で評価する。この仮想解決ではターンを終了しない。
- 実際のゲーム表示では通常どおりダメージマーカーを0.5秒表示してから解決する。

## 評価の循環を防ぐ規則

- 基礎評価は現在状態だけを見る。
- 攻撃プレビューは戦闘後の基礎評価だけを見る。
- `evaluateBattleEntry`は基礎評価と攻撃プレビューだけを見る。
- 展開可能手札価値は、各カードを1回使用した状態の`evaluateBattleEntry`だけを見る。
- `evaluateCoherentMainPlan`は実際に召喚を適用した状態の`evaluateBattleEntry`だけを見る。
- `evaluateCoherentMainPlan`のロールアウト中は召喚以外のメイン行動を選ばない。
- 展開可能手札価値の計算中に、展開可能手札価値を呼ばない。
- 評価関数からGameAIの行動選択を呼ばない。

この依存方向を崩す変更は行わない。

## 計算量の方針

思考時間、探索深度、探索ノード数による打ち切りは実装しない。

- 現在の合法手を1回ずつ評価する。
- Easyは各合法手の直後を評価する。Normal・Hardは各合法手の後、召喚可能な手札がなくなるまで一貫した貪欲ロールアウトを行う。
- ロールアウトは各段階で実状態を更新し、独立候補の点数を加算しない。
- 展開可能手札価値は最大5枚を多項目ナップサックとして計算する。
- 各カードは同じ有効コストの配置候補を最善の1つへまとめる。
- 展開可能手札価値の中から展開可能手札価値を再帰的に呼ばない。
- 同じカード定義、同じ有効コスト、同じ配置結果になる候補は必要に応じてまとめる。

処理時間に問題が出た場合は、時間制限を追加する前に、重複計算のキャッシュと同一候補の統合を行う。

## テスト方針

### 合法手

- 列挙したすべての行動を適用できる。
- マナ不足、進軍不足、フェイズ違いの行動を列挙しない。
- 起動条件を満たさない能力を列挙しない。

### 攻撃評価

- 複数の攻撃候補を合算せず、最善の1グループだけを採用する。
- 通常クリーチャーの破壊では返還マナを差し引いた価値になる。
- 《消滅》の破壊は同コストの通常クリーチャーより高く評価する。
- 《反撃》で自分が失うカード価値を減点する。
- 致死攻撃を他のすべての非致死行動より高く評価する。
- 相手の致死攻撃を許す状態を大きく減点する。
- 現在の攻撃で勝利した状態から、ターン終了や相手ターンの処理へ進まない。
- 勝利点の絶対値が敗北点の絶対値より大きい。

### 能力評価

- 《撤収》によって高価値の召喚が可能になる局面を評価できる。
- 《招集》で味方に合流して勝利できる攻撃を評価できる。
- AIは同じ`CardInstanceId`を同一ターンに2回招集候補へ含めず、次のターンには再び候補へ含める。
- 人間プレイヤーは同じ物理カードを同一ターンに移動先が変われば複数回招集できる。
- 《橋頭堡》の軽減で召喚可能になった場合だけ即時価値が上がる。
- 有効な《採掘》は無効な《採掘》より高く評価する。
- 《捕獲》が進軍1の仮想クリーチャーの配置可能位置を減らす場合だけ評価が上がる。
- 《捕獲》で配置可能位置が1箇所減るごとに0.5点加算する。
- 支払えない《リボ払い》持ちを、手番を渡した後の防御要員として評価しない。
- 《トリックスター》のHP差による実効ステータスが攻撃評価へ反映される。
- 《略奪》で増えたマナによって次回新たに展開可能になる現在の手札を評価する。
- 《略奪》の次回展開価値を計算するために、次ターンの行動探索を追加しない。

### 評価関数

- 同じ公開情報と同じ自分の手札なら、相手の非公開手札や山札順を変えても評価値が変わらない。
- 同じ状態と設定なら常に同じ行動を選択する。
- 各内訳の合計と`total`が一致する。
- パラメータ変更の影響を局面単位で確認できる。
- 自分の手札にあるクリーチャーの予備価値が召喚コストの0.3倍になる。
- 自分の手札にある魔法の基礎予備価値が1枚あたり2.0になる。
- 《生命の雫》の温存価値が、捨て札の青クリーチャー数に応じて0.5倍で1回だけ加算される。
- 《バックドラフト》の行動候補はダメージ解決後の盤面で評価される。
- 相手の手札枚数が変わっても、手札の予備価値は変わらない。
- 展開可能手札価値は、現在マナを複数のカードで重複利用しない。
- 複数の展開候補が同じ勝利または敗北回避を生む場合、勝敗級の差分を1回だけ加算する。
- 展開可能手札価値の計算が再帰しない。
- 何もしない評価には展開可能手札価値を加えない。
- Easyの行動候補は直後の状態で評価し、Normal・Hardでは実際に状態を更新した召喚ロールアウトの最良途中状態を使う。
- ロールアウトが複数召喚を処理し、同じマナ、配置先、攻撃機会を重複利用しない。

### フェイズ進行

- メインフェイズでは攻撃を選択しない。
- 「何もしない」評価以下のメイン行動を実行しない。
- メイン行動を実行するたびに合法手と評価値を再計算する。
- マナと合法手が残る限り、固定回数に制限されずメイン行動を続けられる。
- バトルフェイズでは各攻撃候補と「攻撃しない」を改めて比較する。
- 攻撃する場合と攻撃しない場合を、同じターン進行地点まで解決して比較する。

## 実装順

1. HPが0以下になった時点の勝敗状態と終了判定を定義する。
2. 合法手列挙を実装する。
3. 戦闘計算を演出から分離し、戦闘プレビューとして共通化する。
4. 基礎評価と内訳を実装する。
5. 手札の予備価値と展開可能手札価値を実装する。
6. 自分と相手の攻撃プレビュー評価を実装する。
7. メインフェイズで「何もしない」と各合法手を比較する処理を実装する。
8. バトルフェイズで攻撃候補を改めて比較する処理を実装する。
9. UI上でAIプレイヤーの行動を順番に実行する。
10. 局面テストとAI同士の対戦で係数を調整する。
